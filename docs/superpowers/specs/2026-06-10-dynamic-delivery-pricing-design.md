# Динамическая стоимость доставки (час пик + погода)

Дата: 2026-06-10

## Цель

Стоимость доставки должна учитывать час пик и осадки — по аналогии с
повышающими коэффициентами Яндекс Доставки (бизнес-аккаунта нет, поэтому
своя логика). Надбавки задаются константами; на старте обе равны 0 —
поведение идентично текущему, цифры проставляются позже.

## Конфиг (`lib/delivery-pricing.ts`)

```ts
RUSH_HOURS = [
  { from: "11:30", to: "14:00" },
  { from: "18:00", to: "21:00" },
] // время Краснодара (UTC+3)
RUSH_SURCHARGE = 0    // ₽, надбавка в час пик
WEATHER_SURCHARGE = 0 // ₽, надбавка при осадках
```

## Погода

- Open-Meteo (бесплатный, без ключа): `current=precipitation,snowfall`
  по координатам пиццерии (`PIZZERIA_COORDS`).
- Кэш в памяти процесса на 10 минут.
- Осадки = precipitation > 0 или snowfall > 0.
- Ошибка/таймаут API → считаем «без осадков», заказ не блокируем.

## Расчёт

```
итог = цена_зоны(координаты) + RUSH_SURCHARGE(если час пик) + WEATHER_SURCHARGE(если осадки)
```

- Надбавки суммируются.
- Применяются даже при «бесплатной» доставке от 1500 ₽ (база 0 + надбавки).
- Самовывоза не касаются.

## Серверный расчёт цены (безопасность)

Сейчас клиент присылает `deliveryPrice`, сервер ограничивает максимумом.
Станет:

- Клиент передаёт координаты адреса (`deliveryCoords: [lat, lon]`) в
  payload заказа (они уже есть из карты/геокодера).
- Сервер (`verifyAndPriceLines`) сам определяет зону по координатам и
  добавляет надбавки. Клиентское `deliveryPrice` игнорируется.
- Координаты вне зон доставки → ошибка заказа.
- Заказы без координат (метод pickup) → доставка 0.

## API для корзины

`GET /api/delivery-quote?lat=..&lon=..` (rate limit 30/мин на IP):

```json
{ "base": 249, "surcharges": [{ "reason": "дождь", "amount": 50 }], "total": 299 }
```

## UI корзины

Показывается сразу итоговая сумма, причины в скобках:

- «Доставка: 299 ₽ (дождь)»
- «Доставка: 349 ₽ (дождь, час пик)»
- Без надбавок — как сейчас: «Доставка: 249 ₽»

Никаких «+50 ₽» в интерфейсе.

## Тесты

- Расчёт: зона + час пик + погода, все комбинации, границы окон времени.
- Сервер игнорирует клиентский `deliveryPrice`.
- Недоступность Open-Meteo → база без надбавок.
